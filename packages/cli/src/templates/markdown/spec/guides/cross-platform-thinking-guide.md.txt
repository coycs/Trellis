# Cross-Platform Guide

Apply this guide when code runs on more than one operating system or shell.

## Rules

- Use platform path APIs; never build paths with hard-coded separators.
- Invoke project commands through package scripts where possible.
- Treat executable lookup, quoting, line endings, case sensitivity, and file
  permissions as platform boundaries.
- Keep platform branches at the boundary and share the business logic.
- Test at least one representative environment for every supported platform.

## Review

- Are paths normalized only for comparison and preserved for I/O?
- Do spawned processes receive arguments as an array?
- Does Windows executable resolution handle package-manager shims?
- Are text files explicitly UTF-8?
- Does failure output explain the command and working directory?
